# Caption-Pack API — prototype

Working local prototype of the metered caption-pack micro-SaaS
(spec: `../caption-pack-api-spec.md`).

## Quickstart

```bash
cd caption-pack-api
pip install -r requirements.txt
python make_key.py 500        # prints your API key once — save it
uvicorn app:app --port 8471
```

## Try it

```bash
KEY=cp_live_...   # the key printed above

curl -s -X POST http://localhost:8471/v1/caption-pack \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"topic":"cybersecurity awareness month","audience":"IT professionals","tone":"warm","platform":"instagram","count":3}' | python3 -m json.tool

# balance
curl -s http://localhost:8471/v1/balance -H "Authorization: Bearer $KEY"

# interactive docs (OpenAPI/Swagger UI auto-generated by FastAPI)
open http://localhost:8471/docs
```

## Stripe top-ups (Jeshua's layup — 5 minutes)

The webhook code is done and tested. All he has to do:

1. In Stripe: create a **$10 product** ("Caption API credits — 500 calls"),
   make a **Payment Link**, and in the link settings add
   `?client_reference_id=<key id>` plus metadata `credits=500`.
   (The key id comes from `GET /v1/balance` — Jeshua or I can map
   key → customer when handing out keys.)
2. In Stripe dashboard → Developers → Webhooks: add endpoint
   `https://<host>/v1/stripe-webhook`, subscribe to
   `checkout.session.completed`, copy the **signing secret**.
3. On the server, set env vars and restart:
   `STRIPE_WEBHOOK_SECRET=<signing secret>`
   `STRIPE_TOP_UP_URL=<the payment link>` (also used in the 402 response)

From then on, every completed $10 checkout auto-credits the buyer's key.
No human involvement. Run the regression anytime:
`.venv/bin/python test_webhook.py`

## Security notes

- Only sha256 hashes of keys touch the database; raw keys are shown once.
- `credits.db` is created next to the app — keep it out of git
  (add `*.db` to `.gitignore`).
- Rate limiting is in-memory: fine for one process, needs Redis if we
  ever run multiple workers.
