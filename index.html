Security Review

1. Data minimization

We store the minimum needed to operate the service:

  • Stored: API key hashes (never raw keys), credit balances, timestamps, endpoint called, IP address, user agent.
  • Not stored: request content — your topics, audiences, and tones are never written to disk. We record that a call happened, never what it contained.
  • Not collected: emails, names, or any customer profile data. No account required.
  • Playground: IP + user agent + timestamp only.

2. Key handling

  • Keys are stored as hashes and transmitted as bearer tokens over HTTPS.
  • Revocation is supported and checked on every call.
  • Free-trial keys: 25 credits, 7-day expiry, never convertible or top-up-able — abuse-resistant by design.
  • Operator endpoints are gated by a token that is not stored in the repository.

3. Payments

  • Checkout is hosted by Stripe — card data never touches our servers.
  • Stripe webhooks are signature-verified and idempotent (duplicate deliveries cannot double-credit).

4. No LLM in the loop

Caption-Pack uses a deterministic template engine. Customer input is never sent to a third-party model and never used for training. There is no model to leak into.

5. Known limitations

  • One-person operation. Incident response is via email with a 2-business-day target (per the SLA).
  • MCP key transport. The Smithery MCP deployment currently passes the API key as a query parameter, which can appear in server access logs. Risk is limited (logs are only visible to the service owner). Header-based authentication is the planned hardening item.
  • Entry-level hosting. The API runs on Render and Turso free tiers; their platform security postures apply.

6. Incident response

  • Contact: xena.domingo.ea@gmail.com
  • Suspected key compromise: the key is revoked and a replacement issued.
  • Payment issues: handled through Stripe's dispute and refund tooling.

Privacy Policy

We keep data collection narrow and tied to running the service. This policy explains the limited information needed to provide Caption-Pack and how long that information stays with us.

01 What we collect

When you buy credits, Stripe collects your email address so it can send receipts. API keys are stored only as SHA-256 hashes, never as plaintext. We keep API usage logs—including calls, timestamps, and error counts—to meter credits and prevent abuse. IP addresses are used only for rate limiting: the free trial allows one key per IP every 24 hours, and the playground allows five calls per hour per IP.

02 Payments

Stripe processes every payment. We never see or store your card number.

03 What we never do

We do not sell your data. We do not use your prompts, topics, or captions to train any model. Caption-Pack uses deterministic templates; there is no machine-learning model in the loop.

Free-trial keys and their related logs expire automatically after seven days. Paid keys and credit records remain while you hold credits. Aggregate public statistics—counts only, with no IP addresses or API keys—may be kept indefinitely.
